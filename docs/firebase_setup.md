# Firebase Setup

Enable these products in the same Firebase project:

1. Firebase Authentication (Email/Password)
2. Cloud Firestore
3. Firebase Storage
4. Firebase App Check
5. Firebase AI Logic / Gemini

Deploy rules and indexes from the repository:

```bash
firebase deploy --only firestore:rules,firestore:indexes,storage
```

Create student registry records through a trusted administrator process. Student self-registration is limited to the student role.

Create DSW staff users through a trusted process and set `/users/{uid}.role` to `dsw_officer` or `dsw_director`.

For Android release builds, register App Check with Play Integrity. For a production Flutter web staff dashboard, configure a web App Check provider/site key before enabling enforcement.

## Flutter client configuration

`lib/firebase_options.dart` is generated by the FlutterFire CLI and is required by app initialization. Keep it in version control with `android/app/google-services.json`; these are client app configuration files, not service-account credentials. CI verifies both files and does not need Firebase account credentials to analyze, test, or build the app.

To register another platform or refresh the client configuration, authenticate with an account that can access the existing Firebase project, then run:

```bash
dart pub global activate flutterfire_cli
flutterfire configure --project=<existing-project-id> --platforms=android,web
```

Use the project ID shown in Firebase Console or the current generated configuration; do not substitute a new project ID. Never commit service-account JSON, private keys, or access tokens.
